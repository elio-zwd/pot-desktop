# Pot 社区维护版首阶段决策

本文档记录已经由仓库所有者确认、后续开发不应反复讨论的基础决定。

## 1. 项目身份

- 对外名称：`Pot 社区维护版`
- 性质：非官方社区维护版
- 上游来源：`https://github.com/pot-app/pot-desktop`
- 维护仓库：`https://github.com/elio-zwd/pot-desktop`
- 许可证：继续遵循 GPL-3.0
- 必须保留原作者、原项目和许可证声明
- 不得冒充官方 Pot 或 Manggo

## 2. 稳定基线

- 稳定分支：`custom/main`
- 首阶段基线 SHA：`b535ac2b1f39fead9eb8d0e0a1f95f1e991ff823`
- 后续新分支必须从最新稳定 `custom/main` 的明确 SHA 创建
- 不再从旧的 Schema V2 功能分支继续开发

## 3. 已成为基础能力的功能

以下功能已经完成合并和验收，不再作为实验能力：

- 插件设置 Schema V2；
- 设置分组；
- 密码遮罩；
- 多行输入；
- 条件显示；
- 高级设置折叠；
- 插件结果 Schema V2；
- 六类受控结果区块；
- 统一复制文本；
- 历史记录纯文本；
- 旧版字符串和对象结果兼容；
- 明暗主题与窄窗口适配。

后续变更不得破坏这些兼容边界。

## 4. 初期正式支持

- 正式支持平台：`Windows x64`
- macOS、Linux：可以接受已复现关键修复，但本阶段不承诺正式发布和完整验收
- 不复制上游全平台发布矩阵作为首阶段门禁

## 5. 版本策略

- 首个规划版本：`3.1.0-elio.1`
- 版本必须明显区别于官方 Pot `3.0.7`
- 发布物必须明确标注非官方
- 具体版本写入、安装包命名和发布流程由后续 `chore/custom-release-channel` 完成

## 6. 更新策略

- 自有更新通道完成前，定制版必须关闭或隔离官方自动更新
- 不得使用官方签名密钥
- 不得把更新端点改成不存在的占位服务
- 更新器审计属于 `chore/maintenance-foundation`
- 自有更新服务、签名和安装包品牌化属于后续独立 PR

## 7. 分支策略

- `master`：历史上游跟踪分支
- `custom/main`：社区维护版稳定主线
- `feat/*`：独立新功能
- `fix/*`：独立缺陷修复
- `chore/*`：维护和基础设施
- `port/upstream-pr-<number>-<topic>`：上游 PR 移植
- 禁止直接在 `master` 或 `custom/main` 开发
- 所有开发先创建 Draft PR
- 未经用户明确授权不得转 Ready 或合并

## 8. 维护优先级

优先维护：

1. 插件平台；
2. Windows x64 稳定性；
3. 安全修复；
4. 启动、快捷键、剪贴板、插件安装与执行；
5. 构建与发布链；
6. 主要 AI 接口失效。

默认不承担：

- 全部上游遗留 Issue；
- 所有冷门服务；
- 与 Manggo 全面竞争；
- 首阶段 Tauri 2 迁移；
- 首阶段整套依赖升级；
- 大规模 UI 重写。

## 9. 上游 PR 原则

- 不整批接管上游 PR；
- 每个候选先完整审计；
- 不相关问题必须拆分；
- 优先保留原作者提交和署名；
- 必须在当前 `custom/main` 上重新验证；
- 关闭、无人维护或长期未响应不等于代码正确；
- 所有结论记录在 `UPSTREAM_PORTS.md`。

## 10. 已知独立问题

Windows `tauri_plugin_single_instance` 空指针问题：

- 作为独立运行时问题记录；
- 不属于 Schema V2 回归；
- 不阻塞维护版基础建设；
- 不在基础建设分支顺手升级 Cargo.lock；
- 后续通过独立修复或上游移植流程处理。

## 11. AI 协作方式

- 远端 AI：规划、编写代码、轻量化测试、提交和 Draft PR；
- 本地 AI：拉取指定 SHA、构建和只读验收；
- 本地 AI 不修改代码、不提交、不推送、不合并；
- 提交信息使用 `英文 Tag: 中文描述`。
