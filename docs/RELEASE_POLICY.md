# Pot 社区维护版发布政策

## 1. 身份与许可

- 发布名称统一使用 `Pot 社区维护版`。
- 所有发布页面、安装包说明和更新提示必须明确标注“非官方社区维护版”。
- 项目继续遵循 GPL-3.0，并保留原作者、原仓库与许可证声明。
- 不得使用官方 Pot 或 Manggo 的身份发布、宣传或接受反馈。

## 2. 支持平台

首阶段正式发布目标仅为 Windows x64。

macOS 和 Linux 可以接受已复现的关键修复，但在建立独立构建、签名和验收能力前，不承诺正式发布产物。

## 3. 版本规则

维护版版本格式为：

`上游版本-elio.维护序号`

首个规划版本：`3.1.0-elio.1`。

版本号必须明显区别于上游 Pot 3.0.7，不得让用户把维护版安装包误认为官方包。

## 4. 发布来源

- Release 必须基于已验证的 `custom/main` 精确 SHA。
- 发布说明必须记录 Base SHA、最终 SHA、测试结果和已知问题。
- 开发分支不得直接发布。
- Draft PR 未完成验收、未获得仓库所有者明确授权时不得发布。
- 回滚必须指向上一个已验证的 `custom/main` 发布 SHA，不得通过强推改写历史。

## 5. 发布门禁

正式发布前至少需要：

1. 设置 Schema V2 测试通过；
2. 结果 Schema V2 测试通过；
3. `pnpm build` 通过；
4. Windows x64 安装包构建与基础启动验收通过；
5. YAML、JSON、Markdown 和 `git diff --check` 通过；
6. 确认构建产物不包含 API Key、令牌、证书、用户配置或数据库；
7. 确认自动更新只使用维护版自有端点与自有签名材料，或保持明确关闭。

## 6. 安装包与发布说明

发布物必须：

- 在文件名、Release 标题或说明中标注社区维护版身份；
- 说明正式支持平台和架构；
- 列出上游来源、许可证、主要改动和已知问题；
- 说明是否提供自动更新；
- 说明本维护版问题应反馈到 `elio-zwd/pot-desktop`；
- 不声称官方 Pot 或 Manggo 为本维护版提供支持。

## 7. 更新器与签名边界

当前维护基础分支已经关闭并隔离官方 Tauri Updater：

- 不再连接 `pot-app/pot-desktop` 的官方更新清单；
- 不再使用上游 updater 公钥；
- 启动阶段的更新检查只记录“维护版更新通道未配置”，不发起网络请求；
- 不配置不存在的占位端点。

详细审计见 `docs/UPDATER_AUDIT.md`。

自有更新服务器、维护版公钥、签名私钥、版本写入、安装器品牌化和更新清单生成统一留给独立分支：

`chore/custom-release-channel`

该分支完成并通过验收前，不得重新启用自动更新。

## 8. 历史发布脚本

仓库现有 `updater/updater.mjs`、`updater/updater-for-fix-runtime.mjs` 和相关 package scripts 来自上游发布链，仍指向官方仓库与官方产物。

在维护版发布链完成前：

- 这些脚本只作为历史上游实现保留；
- 不得用于生成维护版更新清单；
- 不得在 CI 中自动执行；
- 后续发布分支必须重新设计并审计，而不是直接替换 URL 后投入使用。

## 9. 已知问题与回滚

每个 Release 必须列出：

- 已知运行时问题；
- 未正式支持的平台；
- 更新器状态；
- 与上游版本的差异；
- 回滚目标版本和精确 SHA。

Windows `tauri_plugin_single_instance` 空指针问题属于独立运行时问题，不在维护基础分支处理，也不得阻塞本治理 PR。

## 10. 禁止事项

未经明确授权，不得：

- 发布安装包或 GitHub Release；
- 使用上游签名密钥、证书或更新端点；
- 把私钥或真实凭据提交到仓库或 Actions Secret 之外的文件；
- 把开发分支、未验证 SHA 或未通过门禁的产物标记为正式版；
- 将 Draft PR 自动转 Ready 或自动合并。
